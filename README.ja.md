# agent-report

[gem-agent](https://github.com/nlink-jp/gem-agent) と
[lagent](https://github.com/nlink-jp/lagent) のセッションの利用概要を、
自分の機械の上で作り、報告に添えるための道具です。

[English README](README.md)

## なぜ

gem-agent や lagent の不具合を報告しても、開発側からはあなたの環境の規模や使い方が
見えません。セッションの記録にはあなた自身の作業が入っているので、そのまま送ることも
できません。agent-report はその記録を読み、決まった項目の数字だけを出します。
セッション数、ターンあたりのラウンド数、コンテキスト量、ツールごとの呼び出し回数と
所要時間、承認の判断、MCP のサーバー数とツール数などです。

- **数字だけ。** 記録の中の会話・コマンド・パス・宣言された目的などの自由記述は、
  出力に一切現れません。組み込みツールの名前は既知の一覧と照合し、一覧にないものは
  「その他」に数えます。MCP のサーバー名は `--mcp-names` を付けたときだけ出ます。
- **何も送らない。** ネットワークを使いません。出力を読んでから、あなた自身が渡します。
- **読むだけ。** 記録を書き換えたり、移動・削除したりしません。
- **記録にないことは「記録なし」と出す。** たとえば起動の仕方（`-p`、`--auto`）は
  記録に残っていないので、そのことと理由を出力に書きます。

## インストール

```sh
brew install nlink-jp/tap/agent-report
```

または [リリースページ](https://github.com/nlink-jp/agent-report/releases) から
`agent-report-v<version>-darwin-arm64.zip` を取得してください（Developer ID 署名・
Apple の公証済み）。

## 使い方

```sh
agent-report                          # 両ランタイム・直近 30 日・表で表示
agent-report --runtime lagent --since all
agent-report --json > report.json     # 同じ項目を JSON で
agent-report version                  # --version と同じ
```

| フラグ | 既定 | 意味 |
|---|---|---|
| `--runtime gem-agent\|lagent\|all` | `all` | 集計するランタイム |
| `--since <n>d\|YYYY-MM-DD\|all` | `30d` | 集計期間（日付はローカル時刻の 0 時） |
| `--json` | オフ | 表の代わりに JSON を出す |
| `--mcp-names` | オフ | MCP サーバー名ごとの呼び出し回数を出す |
| `--sessions-dir <path>` | 各ランタイムの既定 | 記録を別のディレクトリから読む（`--runtime` が 1 つのときだけ） |
| `--version` | | 版数を出す |

記録の既定の場所は `~/.local/state/gem-agent/sessions` と
`~/.local/state/lagent/sessions` です。既定の場所がないランタイムは `missing` と
出します。`--sessions-dir` で指定した場所がないときはエラーになります。

終了コード: `0` 成功、`1` 実行時のエラー、`2` 使い方の誤り。

## 出力の中身

先頭に `schema`（出力形式の版）、`tool`、`tool_version`、`period`（`since` と
`until`。UTC で書くので、あなたのタイムゾーンは出力に載りません）を出します。
続いてランタイムごとに次の項目を出します。

| 節 | 項目 |
|---|---|
| `transcripts` | `found` か `missing`（パスそのものは出しません） |
| `sessions` | 期間内に動きのあったセッション数、再開の回数 |
| `versions`、`models` | ランタイムの版数ごと・モデルごとのセッション数 |
| `turns` | 操作者のターン数と、ターンあたりのラウンド数（n / p50 / p90 / 最大） |
| `context` | セッションごとの最大プロンプト、プロンプトのうちキャッシュされた割合、会話圧縮の回数 |
| `tokens` | 呼び出し元ごと（主ループ、リスク評価など）の呼び出し数とトークン数 |
| `tokens_by_model` | 同じ呼び出し数とトークン数を、ランタイムが呼んだモデルごとに |
| `main_calls` | 主ループのモデル呼び出しを 1 回ずつ見たもの: 1 回ごとの待ち秒数、再試行で失った秒数、そして「プロンプトの大きさ別」「プロンプトが作り直された理由別」「前の呼び出しからの間隔別」に、呼び出し数、プロンプトとキャッシュのトークン数、キャッシュに当たった回数、当たったとき・外れたときの待ち秒数 |
| `retries` | モデル呼び出しのバックオフ再試行を原因別・モデル別に数えたもの、バックオフの秒数、そして数えたセッションのうち再試行を記録するビルドのものが何件か |
| `tools` | ツールを呼んだ応答の数、複数を呼んだ応答の数（とその種類別の呼び出し数、順に実行してかかった秒数、同時に実行した場合の秒数）、組み込みツールごとの回数と所要秒数・実行秒数、不明な名前への呼び出し、MCP の呼び出し数・サーバー数・ツール数・所要秒数・実行秒数 |
| `shell` | レーン別（read / write / operator / unconfined / unrecorded / other。`unrecorded` はレーンを指定しなかった呼び出し）のシェル呼び出し数、タイムアウト |
| `approvals` | 自動承認の判断（段階別）、承認プロンプトでの判断（出どころ別）、プロンプトであなたの回答を待った秒数、フックによる拒否 |
| `interventions` | ラウンド上限・ループ検出による介入 |
| `modes` | 自動承認・読み取り専用で始まったセッション数（再開を含めて 1 セッション 1 回）、モード切替の回数 |
| `empty_model_responses` | 空で返ってきたモデルの応答の数 |
| `not_recorded` | 記録に残っていない事実と、その理由 |
| `anomalies` | 読めなかったディレクトリ・ファイル・行、ヘッダのないファイル、未対応の schema、未知の記録の種類、対応する呼び出しのないツール結果、結果待ちの呼び出しとは別の呼び出しを指す承認の判断 |

記録の中の文字列は、決まった集合に入るものだけを出します。ランタイムが書く列挙値、
既知の組み込みツール名、狭いパターンに合う版数・モデル名・MCP サーバー名です。
版数はリリースのタグか `git describe` の出力に限り（コミットハッシュだけのものは
`dev` と出します）、モデル名は発行元の前置きが高々 1 つ（`google/…`）の ID に
限ります。それ以外は `other`（欄そのものがないときは `unrecorded`）に数えます。
あなたが自分で付けたモデル ID は書いたとおりに出るので、渡す前に `models`・`tokens_by_model`・`retries.by_model` の節を
確かめてください。

ターンは、あなたが打ったメッセージで始まります。ランタイムが自動で入れるメッセージ
（セッションの事実、再開の注記、`!` のシェル実行、中断した呼び出しについての注記）
ではターンを始めません。

ランタイムは 1 つの応答に含まれる呼び出しを順に実行します。呼び出しの所要秒数は、
同じ応答の直前の呼び出しが終わった時点（最初の呼び出しは応答そのもの）から、その
呼び出しの結果までの時間です。承認待ちや `ask_user` への回答を待つ時間も含みます。

実行秒数は、その呼び出しに承認の判断があれば最後の判断の時点から数えるので、
リスク評価とプロンプトでの待ち時間を含みません。実行されなかった呼び出し
（プロンプトやフックで拒否された、または飛ばされた）は実行秒数に入りません。
`ask_user` には承認がないので、その実行秒数はあなたの回答を待った時間です。
`operator_wait_sec` はその裏側で、呼び出しの開始（自動承認の判断があればその時点）
から、プロンプトであなたが答えるまでの時間です。承認・拒否のどちらも含みます。

ワンショット実行（`-p`）はプロンプトであなたに聞かずに拒否し、ランタイムはそれを
あなたの回答として記録します。起動の仕方は記録されないので、その拒否は
`operator_wait_sec` にほぼ 0 秒の待ちとして入ります。

`multi_call_by_kind` は複数の呼び出しを含む応答を、`read_only`（両ランタイムが
何も変えないと定めた組み込みツールと、read レーンのシェル実行。レーンを指定しない
シェル実行も read レーンで動くのでここに入ります）、
`with_mcp_or_web`（それらに MCP・`web_fetch`・`web_search` の呼び出しが加わるもの）、
`other` に分けます。種類ごとに、`sequential_sec` は全呼び出しの実行秒数の合計、
`if_parallel_sec` は応答ごとに最も長い呼び出しだけを足したもので、同時に実行して
互いに遅くならず、すべて同時に始められた場合にかかったはずの時間です（同じ応答の
前の呼び出しで読み込んだツールを使う呼び出しは、同時には始められません）。
ランタイムは中断した呼び出しにもすぐ結果を返すので、それはほぼ 0 秒として数えます。
結果が欠けた応答（ランタイムが応答の途中で止まった）だけは数えないので、ここの
応答数の合計は `multi_call_responses` より少ないことがあります。

`main_calls` は、モデルの時間とプロンプトのトークンがどこに掛かったかを見ます。
呼び出しの待ち時間は、その前の作業を終えた記録 — 答える相手のメッセージ、圧縮、
別のモデル呼び出し — から、その呼び出し自身の usage レコードまでです。つまり
モデルの時間で、再試行があればそれも含みます。プロンプトの半分以上がプロバイダーの
キャッシュから供給された呼び出しを「当たり」とします。同じ呼び出しを 3 通りに
並べ、空の行も必ず出します。

- `by_prompt_size` — すべての呼び出しを、プロンプトの大きさで
  （`under_100k` 〜 `600k_and_over`）。
- `after_reset` — プロンプトが以前に送られたはずのない呼び出し。外れて当然の
  ものです。セッションの最初（`session_start`）、`compaction`・`resume`・`clear`
  の直後、ツール一覧かシステムプロンプトが変わった直後
  （`tools_or_prompt_changed`）。
- `by_gap` — それ以外のすべての呼び出しを、前の主ループの呼び出しが終わってからの
  秒数で（`under_30s` 〜 `900s_and_over`）。ここではプロンプトが前の呼び出しの
  送った内容を繰り返すので、外れはキャッシュが手放したことを意味します。間隔には
  その呼び出し自身の時間が入るので、十分に遅い呼び出しは自分のせいで後ろの行に
  入ります。

`retry_sec_total` は、`wait_sec_total` のうち、応答した試行が始まるまでに使った
時間 — 断られた試行と、そのたびのバックオフ — です。

`retries` が数えられるのは、ランタイムが書いたものだけです。gem-agent は v0.102.0
から再試行を記録し、lagent は記録しません。`sessions_recording` は、数えた
セッションのうち再試行の記録を持ちうるものの件数です。`sessions_recording: 0` の
隣の 0 件は「記録なし」であり、「再試行なし」ではありません。再試行のエラー文は
出しません — 出すのはステータス（`429`、`503` など）だけです。

表と `--json` は同じデータから作ります。表は JSON を字下げした行に並べたものです。

## 対応環境

Apple Silicon の macOS のみです。読む対象の 2 つのランタイムと同じです。
